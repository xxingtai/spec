# references/card-filling.md — 卡片填写与证据标注（防编造）

> 对象：reference 详档的符号/接口卡片与各页叙事节。目标：**调用者视角**（怎么调、返回什么、错了怎么看），不是源码翻译。
> 原则：**机器能证明的交机器（inventory），AI 只写它读了源码后能说清依据的话。**

## 1. 卡片格式（机器生成，勿改结构）

`extract` 生成的卡片骨架（位于 AI-GEN 机器区内）：

```markdown
### <语义名>

- 签名：`<inventory signature>`（file <path>:<line>, evidence: 事实）<!-- @FUN-xxx -->
- 引用计数：refs=0（…）      ← 仅零引用符号有此行（机器事实）
- 用途 / 参数 / 返回 / 错误：<!-- TODO AI 依源码填写 -->
```

- AI **只填**「用途 / 参数 / 返回 / 错误」行；签名行、隐藏锚点 `<!-- @ID -->`、引用计数行都是机器维护，**禁止手改**。
- 标题只写语义名；同模块重名时机器自动加文件限定。删除一张卡片 = `check` 报 orphan。
- 接口/绑定卡（MSG-/SRV-/TOP-/SVC-/NDE-）同规则：填「用途 / 语义」行。
- 零引用符号（卡片有 refs=0 行、或 brief 工单 zero_refs 列出）：如实写明"未被使用（dead）"或注明疑似框架回调，**不得凭命名推断用途**。

## 2. 四级证据标签

| 标签 | 含义 | 何时用 | 示例 |
|:---|:---|:---|:---|
| **事实** | 直接可见于代码/配置文件/inventory | 签名、路径、路由、常量默认值、可见的调用 | `- 请求体：{username, password}（evidence: 事实，见 FastAPI 模型 AuthBody）` |
| **推断** | 从代码可推导，但需给依据 | 由调用关系/分支推断职责边界 | `- 此函数负责 token 刷新（evidence: 推断，调用链 refresh()→auth_middleware）` |
| **假设** | 代码无法证明，AI 猜的 | 无依据的意图、why | `- 推测支持多租户以隔离数据（evidence: 假设，需人工确认）` |
| **缺失** | 源码不足，无法确认 | 无测试、无类型、历史丢失 | `- 字段长度 unknown（evidence: 缺失，DDL 未入库）` |

## 3. 强制规则

1. 每条语义结论带且只带一个证据标签；机器行（签名/路径/ID/引用计数）默认事实，不重复标注。
2. **拿不准写 `unknown`，禁止省略或伪造**：字段长度/可空/索引、行为细节、外部依赖行为，凡代码没说清的一律 unknown。
3. `假设` 与 `推断` 在正式合入前默认要求人工确认点通过；`推断` 需在句内写明依据链（谁调用谁/哪个分支/哪个测试佐证）。
4. 免责句（architecture/module 文档开头一句即可）：
   > 本文档由 dev-docs 从代码反建，记录"代码里的实现事实"；设计意图（why）在「人工补充」区由维护者补写，未补前不代表历史决策。
5. 禁止为"显得完整"编造：不存在的参数、不存在的错误码、来源不明的调用方式，一律不写。

## 4. 常见误用对照

| ❌ 编造 | ✅ 正确 |
|:---|:---|
| `错误码 5002 表示余额不足`（源码无此码） | `错误处理：返回 4xx（evidence: 事实，见 raise HTTPException(400)）；具体码表 unknown` |
| `此接口幂等，可安全重试`（无依据） | `幂等性：未见去重键（evidence: 假设，需确认）` |
| 复制测试里不存在的调用当示例 | 示例必须来自 `tests/` 真实用例（见 §5） |
| 脑补字段 `status: enum(0,1,2)` | `status: unknown（evidence: 缺失，无枚举定义可查）` |

## 5. 示例质量要求（核心防幻觉点）

1. 示例**必须取自测试**：先在 `inventory.json.tests` 里找覆盖该符号的用例（tested_by 启发），再打开测试文件摘抄真实调用。
2. 找不到覆盖用例：不编造，写 `<!-- TODO 无现成测试，示例待补（不臆造） -->`。
3. 示例应剪裁（去掉断言噪声）但**保持真实参数与语义**，标注来源文件。

## 6. 风格红线

- 标识符/路径/签名不翻译、不改写；叙述语言中英二选一（调用方声明）。
- **行内证据用短式**：`（据 file:line）`——如 `（据 src/pkg_core/DroneController.cpp:88）`；长式 `（evidence: 事实，见 …）` 仅用于需要展开依据链的「推断/假设」。证据标注不应比正文长。
- **引用格式硬规范（check 与 fixrefs 的机器假设，违反必返工）**：
  1. 一律 `路径:单行号`，**完整相对路径**——禁止 basename 短写（`据 runtime.py:9` 在多义文件名下 100% 解析失败，实测 300+ 处返工）；
  2. **禁止行区间**（`path:2-5`）——fixrefs 按单行语义工作，区间首数字会被当独立引用误修出倒序；需要指一段逻辑时引用**关键行**（定义行 / 决定性行），或引用签名行同款 file:line；
  3. 拿不准行号时引用卡片签名行的 file:line（机器保证有效）。
- 卡片独立成段，锚点格式勿改（对账依赖）。
- 不写空话（"该函数非常重要"）；写不出就 unknown/TODO，别堆形容词。
- 变更记录（Added/Changed/Deprecated）放「人工补充」区由人维护。
- 人工区（why）与机器区（what）分界：AI-GEN 区内写 what/how；「人工补充」区写 why，AI 可提议但必须标假设，人工确认后才 promote。
