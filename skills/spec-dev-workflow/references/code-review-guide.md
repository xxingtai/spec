# Code Review 审查指南

## 五个审查维度

### 1. 安全性（优先级：最高）

| 检查项 | 说明 |
|--------|------|
| SQL 注入 | 所有查询使用参数化语句或 ORM |
| XSS | 用户输入在渲染前必须转义/清理 |
| CSRF 防护 | 状态变更请求需验证 CSRF token |
| 认证 | 每个受保护端点必须验证用户身份 |
| 授权 | 资源访问必须基于用户权限范围 |
| 输入验证 | 所有外部输入在服务端做类型、长度、格式验证 |
| 敏感数据 | API 密钥、密码、token 不得出现在源码或日志中 |
| 依赖安全 | 新依赖来自可信源，无已知 CVE |

### 2. 性能（优先级：高）

| 检查项 | 说明 |
|--------|------|
| N+1 查询 | 数据库访问批量处理，避免循环单查 |
| 内存泄漏 | 事件监听器、订阅、定时器必须清理 |
| 懒加载 | 重型组件和路由使用懒加载 |
| 缓存策略 | 高开销计算和 API 响应使用缓存 |
| 数据库索引 | 查询字段已建立索引 |
| 分页 | 列表接口使用分页，避免 SELECT * |

### 3. 正确性（优先级：高）

| 检查项 | 说明 |
|--------|------|
| 边界处理 | 空数组、空字符串、零值、负数、最大值 |
| 空值处理 | 可空值使用前检查，使用可选链或守卫 |
| 错误传播 | 异步调用错误被捕获处理，Promise 不被静默吞没 |
| 状态一致性 | 多步变更事务性，部分失败不破坏整体状态 |
| 时区处理 | 存储用 UTC，展示层做时区转换 |

### 4. 可维护性（优先级：中）

| 检查项 | 说明 |
|--------|------|
| 命名清晰 | 变量、函数、类名能表达意图 |
| 单一职责 | 每个函数/类只做一件事 |
| DRY | 重复逻辑提取为共享工具 |
| 复杂度 | 函数分支复杂度低，避免深层嵌套 |
| 死代码 | 删除注释掉的代码、未使用的导入 |

### 5. 测试（优先级：中）

| 检查项 | 说明 |
|--------|------|
| 覆盖率 | 新逻辑有对应测试，关键路径有正反用例 |
| 测试质量 | 测试行为而非实现细节 |
| 测试独立 | 每个测试自包含，执行顺序不影响结果 |
| 回归测试 | Bug 修复包含复现原始 Bug 的测试 |

## 严重等级

| 等级 | 标签 | 含义 | 是否阻塞 |
|------|------|------|----------|
| CRITICAL | `[CRITICAL]` | 安全漏洞、数据丢失、生产崩溃 | 是 |
| MAJOR | `[MAJOR]` | Bug、逻辑错误、性能显著退化 | 是 |
| MINOR | `[MINOR]` | 降低未来维护成本的改进 | 否 |
| NIT | `[NIT]` | 风格偏好、命名建议、琐碎清理 | 否 |

## 反馈原则

- **具体** — 指出具体行号和问题
- **解释** — 说明风险或后果，不只是规则
- **建议** — 提供具体替代方案或代码片段
- **提问** — 主观问题用提问方式："你觉得...如何？"
- **肯定** — 表扬好的解决方案和测试
